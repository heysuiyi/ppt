| --- | --- | --- |
| F0 | 已实施，本地验收通过 | 生产链路的会话展示边界、临时状态隔离和协调切换 |

### 完成门槛

- `/new` 后进入新空会话，旧工具不再作为当前活动出现；旧存储和已有终端滚动历史未删除。
- `/resume` 后标题/上下文与内容属于同一 Thread；恢复未完成 Query 仍使用宿主权威检查点。
- 切换失败或取消，原绑定、草稿与光标保留。
- 旧 Run 的迟到预览、旧输入 generation 不能覆盖新绑定或批准新交互。
- 所有新契约已有真实调用路径，不存在兼容分支、假默认场景或未消费字段。

## 3. F1：连续启动与精简布局

### 修改范围

- `cli/terminal/terminal-controller.ts`
- `cli/terminal/interactive-renderer.ts`
- `cli/terminal/status-line.ts`
- `cli/terminal/welcome.ts`
- 必要时调整现有启动装配，保留同一输入 owner

### 工作项

1. 从启动到 ready 保持同一根布局与编辑器。欢迎内容在第一帧按同一规则安排，不等宿主 ready 才突然插入；初次配置通过现有 setup 焦点处理。
2. 将“可编辑”与“可提交”分开：初始化中的文字留在主草稿，Enter 不清稿、不排队、不激活模型。不得照搬 cooked 预绘破坏秘密输入隐藏。
3. 常驻上下文仅使用模型名与工作区；读取结构化 `modelName`，不再把厂商/套餐连接标签直接放入状态栏。
4. 移除默认“就绪”、工具模式前缀、常驻 Enter/Alt+Enter 教学和反复“草稿不排队”。完整内容仍可从 `/status`、`/tools`、`/help`、`/hotkeys` 获取。
5. 将 Working、阻塞和局部操作提示放在各自区域；补全不改模型/路径行的含义。错误和安全信息不因减行而消失。
6. 欢迎块随对话自然滚走，不在首条提交时整块消失，不反复归档；会话恢复不重播启动欢迎。普通刷新/resize 不执行启动清屏。
7. 上下文与 editor slot 保持固定相对顺序；窄屏按列宽缩路径/次要字段，不靠全字段换行。

### 完成门槛

- 普通空闲无问题时只有必要上下文与输入；没有厂商、能力教学或额外“就绪”行。
- 快/慢初始化、首次配置、提前输入/Enter 均不丢稿，不产生假 ready。
- 发送时欢迎内容连续，没有旧的“欢迎块清空→输入整体上移”路径。
- `/` 开合不重建主编辑器，模型选择器内仍能区分不同连接。
- 40×12、80×24、120×30 及 NO_COLOR 均可用；不承诺任意终端、字体或 IME 已认证。

### 完成门槛

- 首段真实正文在 completed 前显示；后续正文确实追加，不在最终返回后重播打字。
- 正文与工具顺序正确，一次调用不因状态变化出现多张重复卡。
- 最终内容与预览不一致时展示权威结果；没有重复答案或中间人为清空帧。
- 成功、失败、取消和 waiting 后，既有 applied/unknown 提示不丢失。
- 存储提交语义未被 UI 退休替代，print/JSONL 不输出临时预览或 TUI 状态。

## 5. F3：焦点、等待与错误返回

### 工作项

1. 补全作为主输入附属列表；selector 临时占 editor slot；关闭时归还同一草稿和合法焦点，不盲目恢复已被新审批替换的旧焦点。
2. 局部 Esc 一次只处理一层。运行中编辑仍不排队；Enter 不消费未发送草稿，不复制 OMP 的 steering/follow-up、双击退出和审批拒绝传播。
3. 审批保留权威交互身份、安全摘要和显式选择；空 Enter/Tab 不批准，Esc 不代替拒绝，Ctrl+C 取消、EOF 保持 waiting 继续沿用现有契约。
4. 基于 F0 核实的公开分类处理失败：可恢复模型失败留在当前会话并恢复主输入；存储/租约/绑定不确定等故障明确阻塞或安全退出。不增加自动重试或工具重做。
5. 面板异步加载和会话切换的活动提示覆盖完整操作，不在内部 await 之间短暂回到“就绪”或泛化的“当前操作未结束”。
6. 错误、一般反馈与输入纠错仍按作用域解除；编辑不能抹去持久阻塞，无关帮助命令不能清除模型/权限问题。

### 完成门槛

- 补全、模型目录、能力目录、安全输入、工具详情和审批均能按其语义返回，不丢主草稿。
- 审批前不读取受保护文件，批准后才消费真实结果；拒绝、取消、EOF 的权威状态不同且正确。
- 请求取消后保持结算态，直到权威结果；取消不抹去外部影响。
- 可恢复失败后下一次显式提交是新 Query，不自动续跑失败/终态 Query。
- 不安全故障没有假装恢复输入并继续写入，退出失败仍为非 0。

### 6.1 必须跑的连续场景

| 场景 | 必须观察到的结果 | 证据 |
| --- | --- | --- |
| 快/慢启动与首次配置 | 同一界面/草稿贯穿；提前 Enter 不丢稿、不发送；安全输入不回显 | 真实 CLI/TTY，受控延迟和独立配置根 |
| 首页→补全→模型目录→返回 | 上下文顺序稳定，名称/说明对齐，原草稿及光标恢复；接受补全不执行 | 实际按键或精确原生输入及画面观察 |
| 无插件对话 | 提交立即反馈，真实 delta 先于 completed，最终答案一次出现 | 生产入口、真实 SDK 到本地受控 HTTP |
| 正文→工具→正文 | 同一调用原位结算，前后文本顺序正确；成功后无重复活动卡 | 受控模型 + 临时工作区，核验实际文件效果 |
| 等待/审批/恢复 | 批准前不读取，批准后消费结果；拒绝、取消和 EOF waiting 不混同 | 真实 Node 进程、权威检查点和租约 |
| 新建/恢复会话 | 不显示旧活动，目标上下文与历史一次交接，失败保留原绑定 | 至少两个独立 Thread、成功和失败切换 |
| 失败与取消 | 可恢复错误回主输入；持久化/关闭等不安全错误停止；影响语义不丢 | 受控故障、输出、检查点及退出码 |
| 尺寸和内容 | 40/80/120 列及高度变化，中文、长路径、粘贴和已有字素边界正确 | 实际 TTY；复杂 emoji/IME 另报限制 |
| 输出与退出 | print/JSONL 无菜单、ANSI 或预览污染；raw/光标恢复，无迟到输出 | 现有集成 + 真实终端退出观察 |

### 7.3 真实终端与本地模型

生产 `runCli`、真实 NodeHost、Windows raw/TTY、DPAPI 配置、SQLite、隔离工作区，以及 OpenAI Responses SDK 到 loopback 服务。使用 `WriteConsoleInputW` 精确输入和 `ReadConsoleOutputW` 观察字符单元；没有伪造 isTTY/setRawMode。5 个独立 CLI 进程，共 10 次本地 SDK 请求，没有远程模型调用。

| 场景 | 实际观察 |
| --- | --- |
| 慢启动与首页 | 受控延迟 host.open；提前输入 BOOT_DRAFT 并 Enter，模型请求为 0，ready 后草稿保留且输入行不跳；普通空闲无厂商/工具模式/常驻教学 |
| 补全与模型目录 | Alt+M 切入目录，Esc 先返回连接组、再返回主草稿；Tab 接受 /model 后仍是草稿，未触发模型。厂商仅在明确打开的目录分组等详情中出现 |
| 真实增量与 resize | response.completed 保持未发送时看到 FIRST_LIVE；运行中中文草稿及 Enter 未排队。80×24→40×12→120×30 实际尺寸变化后保留草稿，释放 SECOND_LIVE 后最终回答只显示一份 |
| 文件批准与顺序 | READ_NOTES 等待审批；Tab、空 Enter、Esc 均未批准，也未产生结果请求。等待后替换 notes.txt 为新随机校验码，明确选择允许后真实工具结果携带新码，随后 SDK 消费该结果；最终顺序为正文→工具→后续正文 |
| 拒绝与取消 | 明确拒绝产生工具错误，后续模型收到拒绝结果；另一次活动响应按 Esc，权威 cancelled，未完成正文撤下，租约释放 |
| 模型错误后继续 | 本地 HTTP 401 产生权威 AUTHENTICATION failed；终端保留输入，下一次显式提交以另一 Query 完成。不是自动重试或远程认证验收 |
| 新建成功/失败 | 宿主端口注入明确 HOST_SWITCH_REJECTED 后保留原视图；再次新建成功后无旧活动。该注入不是实际 SQLite 写故障证据；最终进程复核确认提示和安全拒绝各只显示一份 |
| 交互恢复 | /resume 搜索目标 Thread、确认后加载其用户/助手历史，不带上一次活动卡；最终确认文案明确恢复既有绑定，取消后返回原场景 |
