# M4 执行计划：宿主消费侧迁移与收口

状态：M4-A、B 已实施并完成各自本地验收，C～E 待实施。CLI 与新桌面的既有接入是本阶段输入；证据见 [A 实施记录](m4-a-host-boundary.md#9-实施与本地验收记录)及 [B 实施记录](m4-b-desktop-lifecycle.md#8-实施与本地验收记录)，不因两个切片完成就宣布整个 M4 完成。

## 1. 目标与依据

依据 [AGENTS.md](../../AGENTS.md)、[整体路线](../project-plan.md#6-通用-harness-演进路线)及 [M3 最终验收](m3-d-recovery.md#137-修复实施与最终验收记录)，将实际消费侧收敛到 Harness 公开输入、事件和结果协议，形成可追溯的双宿主交付边界。

M4 不再是“从零接入 CLI/桌面”。目标是：消除桌面对终端呈现机制的耦合；补齐双宿主身份、授权、观察和关闭的实际验收；明确历史数据兼容性；删除本切片已无调用的旧路径，并完成当前产物消费验证。

完成本阶段不等于迁完 PPT、Skill、子 Agent 或全部旧业务，也不等于完成 UI 设计体系 U3–U5。

## 3. 范围与非目标

### 3.1 本阶段范围

- Node 宿主公共机制与 CLI/桌面展示适配的职责收敛。
- 双宿主通过公开协议执行、展示、回答待决交互和关闭。
- 桌面 Main/preload/renderer 边界、窗口身份和陈旧结果隔离。
- 当前通用 Harness 会话的兼容说明及跨进程恢复验证。
- 本切片旧调用迁出、无用实现删除、边界门禁及实际产物验收。

### 3.2 明确不做

- PPT 工具插件化、预览/导出迁移，Skill、子 Agent、上下文压缩、并行调度或动态发现。
- 因目录调整新增独立 host 包、全局容器、自动装配框架或第三套运行时。
- 全量删除旧 Agent/Gateway、旧数据库或领域服务；未迁出的领域不是死代码。
- 合并桌面/CLI 数据根、迁移历史 PPT 执行快照、转换 DPAPI/safeStorage 密文。
- P3 第二持久化后端、P4 存储迁移/包化、模型厂商扩展、全量日志迁移或 UI 风格重做。
- 自动抢占写租约、自动续跑未知副作用、承诺事件队列有界或任意管道阻塞下仍推进。

## 4. 跨切片契约

1. **执行来源**：`run()` 创建 Query；恢复从宿主权威存储读取，保持 Query、生成新 Run。renderer/终端不提交 checkpoint、租约或重建的执行状态。
2. **身份与选择**：工作目录、模型连接、工具权限和执行版本在会话/执行边界绑定。UI 当前选择不能改写旧会话；旧 scope/revision、会话或 Run 的异步结果不能覆盖新上下文。
3. **待决交互**：回答匹配持久化 Query/interaction。只支持公开可解释交互；未知版本明确不可回答，不以普通文本“同意”续跑，不按工具名称自行授权。
4. **消息与展示**：临时正文/公开推理可以展示，只有权威提交进入规范历史。断流、截断及持久失败不能显示 completed；工具原始输入/结果、私有 replay 和 SDK 异常不进入通用 UI DTO。
5. **观察与所有权**：订阅只观察；停止观察不等于取消。窗口拥有桌面宿主，应用拥有共享配置/日志；先停止受理并排空运行，再关闭依赖。
6. **取消与退出**：用户取消为 cancelled，宿主关闭中断运行；已持久化 waiting 在正常退出后仍是 waiting。EOF 不是取消，强杀不是正常关闭。
7. **端口与安全**：configuration 的原签发计划只由同一运行时解析；Key 留在宿主/适配边界。文件能力复用 tools 工作区限制和独立授权策略，不因消费端改造放宽权限。
8. **模块边界**：Core 不依赖 app、cli、Electron、SQLite 或终端类型；CLI 不反向依赖 app。共享机制不包含 raw mode、ANSI、终端输入面板或 React/IPC。

## 5. 执行切片

### M4-A：宿主机制与展示适配收敛

详细步骤及证据见 [M4-A 执行计划](m4-a-host-boundary.md)：保留现有物理落点，已拆分中立 NodeHost 与 CLI 配置适配，A0～A5 的类型、安全投影、双端调用、依赖门禁及本地验收完成；B～E 保持待实施。

前置：确认公开协议与全部调用方，先查导出符号引用，再做修改。

主要落点：`cli/host/host-contract.ts`、`node-host.ts`、`session-history-projection.ts`，`cli/terminal/`，`app/main/agent-host/desktop-host.ts` 及两侧调用方。

- 区分通用会话操作、配置交互与终端展示职责；保留现有 SessionHost/NodeHost 机制，不再实现一套执行调度。
- 为桌面实际需要的会话、模型、历史、安全错误与交互描述提供具名窄契约。领域无关且双端共用的投影由宿主机制拥有；ANSI 清洗、终端布局和输入回调仍由 CLI 拥有。
- 以职责决定落点，优先复用现有文件；只有实际跨宿主模块边界需要时才移动共享实现，不预设新增 workspace 包。若需移动，同轮迁移全部引用并删除旧别名。
- 桌面不再通过 `cli/terminal` 获取 DTO、错误及交互投影；CLI 的配置向导和单输入 owner 保持终端侧。不是把 `TerminalHost` 原样改名后保留全部终端依赖。
- 通过现有依赖门禁约束双端方向，禁止 Main/renderer 深入 Core 内部；不写源码字符串或导入数量断言。

完成门槛：双端使用同一公开执行机制；无插件对话和文件审批实际运行；桌面不依赖终端呈现模块；CLI 不依赖 app；既有公开消息、JSONL、绑定及存储格式保持兼容。确需协议版本变化时先列受影响恢复数据和拒绝策略，不静默升级。

### M4-B：桌面消费与生命周期闭环

详细设计及完成证据见 [M4-B 执行计划](m4-b-desktop-lifecycle.md#8-实施与本地验收记录)：B0～B6 已实施并完成本地验收，覆盖主文档身份、异步结果裁决、窗口/应用关闭、双窗口写竞争与原生目录选择；未改变持久格式或扩展为 Core 并发调度。

前置：A 的宿主契约稳定。

主要落点：`app/main/agent-host/`、`app/shared/harness-ipc.ts`、`app/preload/`、`app/renderer/src/desktop/`、`app/main/index.ts`。

- 核验所有请求和事件的可信 sender/主 frame；窗口、导航和关闭后不能继承旧观察权限。
- 验证首段事件早于 run 返回、快照晚完成、切换工作区/会话、重复发送、重复审批与关闭交错。保留现有身份/修订机制，不能靠延迟、重试或吞错规避竞争。
- 核验 active、waiting、idle 的窗口关闭与应用退出；共享配置和日志不得在运行排空前关闭，一个窗口关闭不影响另一个窗口拥有的执行。
- 原生目录选择器完成“打开→确认→绑定真实目录”的实际操作；取消选择不改变原工作区。最近目录路径不再替代这项验收。
- 界面保留失败草稿与可操作错误；取消后的临时文本不进入历史，订阅卸载不伪装成执行取消。

完成门槛：真实 Electron 窗口操作和持久核验共同证明状态；两个窗口可隔离不同会话，同一 Thread 的写竞争仍由既有存储准入拒绝，不隐式排队或新增并行调度。

### M4-C：数据兼容与恢复边界

前置：A 稳定；可与 B 的 UI 实施并行，但共用恢复契约不能各自修改。

| 数据来源/变化 | 计划策略 | 验收要求 |
| --- | --- | --- |
| 当前桌面 Harness 会话 | 在原桌面环境恢复 | waiting 正常退出，新 PID 原 Query/新 Run 完成，租约释放 |
| 当前 CLI Harness 会话 | 在原 CLI 环境恢复 | EOF 保持 waiting，新 PID 显式恢复；不能以 Ctrl+C 代替 |
| A 改造前的 Harness waiting | 如未改变协议/格式应继续兼容 | 用改造前实现生成夹具，再以改造后进程恢复；无旧二进制证据时明确限制 |
| 同连接密钥轮换 | 按既有连接身份规则处理 | 不打印密钥，核验恢复使用同一绑定身份 |
| 目录、连接身份、权限或不兼容版本变化 | 按既有绑定/版本规则拒绝 | 不调用模型/工具、不消耗审批、不收养旧 binding、不重置累计预算 |
| 旧 PPT/旧 Agent 历史 | 保留原库与领域归属，不转成 Harness 快照 | 不混列为可恢复的新会话，不触碰生产库，不隐式创建迁移记录 |
| 桌面与 CLI 之间切换 | 数据与保护方案保持隔离，无跨宿主自动续跑 | 不复制密文或借另一宿主身份绕过恢复检查 |

完成门槛：实施记录列清格式/版本是否改变、兼容样本来源及实际新旧 PID。任何恢复拒绝都不能靠重建客户端状态或自动重做 dispatched 工具绕过；第二后端不作为 M4 前置。

### M4-D：旧调用退出与失效路径删除

前置：B/C 覆盖相关消费路径，先证明替代能力和数据策略可用。

主要落点：`app/main/index.ts` 的注册与装配、旧/新 preload 和 IPC、旧 renderer、`app/main/agent/` 及其实际调用方。

- 逐入口记录“调用方、能力、数据来源、替代路径、迁移状态、保留理由”；从生产入口查到真实调用，不以目录名称或默认页面不可见判死代码。
- 已由新桌面替代且无领域消费者的通用聊天入口，同轮迁移全部调用、删除注册/桥接/适配/无用测试及文档引用，不保留兼容别名或双执行开关。
- 仍服务 PPT 或其他未迁领域的入口保留原行为和明确依赖，不能以新聊天接入完成为由删除 Gateway、领域提交或历史恢复实现。
- 共用资源仅在最后调用迁出后移除；禁止把剩余旧业务导入 Core，或让新桌面回调旧 Agent 作为静默降级。

完成门槛：本切片被替代的通用路径没有剩余调用或注册；保留项都能指出实际领域依赖与独立退出前置。若不存在可安全删除项，必须记录调用证据，不为满足删除数量扩大迁移范围。M4 完成不宣称整个旧链路退出。

### M4-E：真实产物与总验收

前置：A～D 的实现和相关回归完成。

- 运行当前 Node CLI 生产/开发入口与真实 Electron 构建入口，不用浏览器 `ui:dev` 或仅类型检查替代。
- 在独立临时 home、执行库与工作区运行下节矩阵，采集实际状态、规范历史和租约证据；不输出完整模型运行对象、密钥或私有 replay。
- 实际启动本轮 Windows 目录打包/ASAR 产物，验证新桌面、配置保护、模块解析及等待恢复；不借用前阶段 ASAR 数字。安装器、签名和发布认证不在本阶段范围。
- 回写本文件实施记录，并同步整体路线与计划入口；历史证据保留原范围，阻塞项如实列出。

完成门槛：下节所有必测行通过，受影响调用/文档已迁移，失效路径已删除。未完成的必测行只能标待完成，不能以“后续补验”宣布 M4 完成。

## 6. 行为验收矩阵

默认使用受控模型/本地 HTTP 与真实文件/SQLite，不产生远程厂商用量。需要远程验收时，先说明模型、场景与 API 用量范围，使用已有授权配置，结果单独归档。

| 场景 | 入口与动作 | 必须观察的事实 |
| --- | --- | --- |
| 无插件基线 | CLI 与桌面各完成普通对话 | 不暴露文件工具，不因未安装业务能力无法启动；仅权威完成进入历史 |
| 文件授权 | 临时工作区含随机 UUID，审批前/批准后分别取证 | waiting 时无文件内容、无活动租约；批准后真实读取并被模型消费 |
| 拒绝与取消 | 双端拒绝审批、运行中取消及 waiting 取消 | 拒绝不执行工具；取消为 cancelled，已发生影响不被抹掉，租约释放 |
| 持久恢复 | CLI EOF、桌面 waiting 正常退出，再各以新 PID 恢复 | 同 Query、新 Run；回答不成为新用户请求，不重复执行未知副作用 |
| 身份与过期结果 | 重复回答、旧 interaction、过期快照/Run、模型/目录/权限变化 | 陈旧结果不能覆盖新会话；不兼容恢复明确拒绝，不静默改绑定 |
| 观察与输入 | CLI 慢输出/退出观察、桌面卸载订阅后重读权威状态 | 观察不驱动执行，不把断订阅当取消；CLI stdin/raw mode 仍只有单 owner |
| 窗口与关闭竞争 | 两窗口切会话、同 Thread 竞争、active/waiting 关闭与应用退出 | 身份和资源隔离；busy/冲突明确；先排空再关依赖；不自动抢租约 |
| 目录选择 | 原生选择器确认与取消 | 确认后绑定实际目录，取消不改旧选择；不以预写最近目录代替 |
| 配置与保密 | 双端配置读取、模型选择/失效与错误返回 | 不回显 Key/SDK 原始异常/私有数据，不自动换模型或降级凭据保护 |
| 历史与产物 | 改造前 waiting、新打包 ASAR、新 CLI 产物 | 兼容规则符合第 5 节；包产物解析成功，开发夹具不进安装产物 |

永久测试只覆盖合理的消费可见回归风险，复用 `tests/desktop-harness-host.test.ts`、`desktop-workspace.test.tsx`、`desktop-settings.test.tsx`、`general-agent-development-host.test.ts`、`general-agent-host-binding.test.ts` 及现有 CLI 回归。真实桌面、原生选择器和打包行为必须实际运行；临时验收脚本用后删除，不以 mock 回声测试接线。

## 7. 执行顺序与检查命令

顺序为 A → B/C → D → E。A 先稳定共享契约，B 与 C 仅在修改面独立时并行；共享文件由同一集成者拥有。每个切片先确认当前实现与引用，遇到缺陷先复现再修复，不以现有计划当作缺陷证据。

按影响范围执行现有命令，不在多个并行任务中重复重建共享产物：

```text
npm.cmd run typecheck
npx.cmd vitest run tests/desktop-harness-host.test.ts tests/desktop-workspace.test.tsx tests/desktop-settings.test.tsx tests/general-agent-development-host.test.ts tests/general-agent-host-binding.test.ts
npm.cmd test
npm.cmd run test:integration:harness
npx.cmd biome check <本次修改的受支持文件>
npm.cmd run build
npm.cmd run agent -- --help
npm.cmd run agent:dev -- --help
```

`--help` 只验证入口加载，不代替对话、审批或恢复验收。实际桌面从构建/打包产物启动；打包按现有 Windows 构建配置执行并记录实际命令。类型/边界、单元测试、实际入口、本地 SDK/HTTP 和远程厂商分别记录，不汇总成超出证据的兼容性结论。
