# 独立页面 UI 设计体系：使用规则、组件与场景执行方案

[返回计划目录](README.md) · [项目整体规划](../project-plan.md)

状态：U0–U2、R1 及 R2 会话/设置切片已实施。根据用户提供的 DeepSeek Harness、Cursor 截图，默认入口已改为会话工作区，模型管理与连接编辑迁入分类设置；R2 的浏览器和独立 UI 门禁通过，详见第 12.4 节。全仓回归仍有 5 项本轮未修改范围的 CLI 渲染失败。**本地验证不等于用户认可新风格**；完整 U3–U5、后端及生产 UI 切换仍不在本轮范围内。

## 1. 目标与范围

本轮建设一套能够独立运行、具有清晰使用规则的页面 UI 体系。采用新目录、新实现和独立预览入口；现有生产 UI 保持原样。先完成组件与页面交互，再在下一步另行设计后端交互和生产迁移。

完成标准不是“列出组件”或“展示静态效果”，而是：面对同一场景，可以依据规则选出组件；组件默认行为符合契约；页面能通过本地受控状态演示完整交互；规则中的错误用法有明确替代方式。

本体系服务于 React DOM 页面，不承担 CLI 的终端渲染。页面与终端可遵循一致的交互原则，例如关闭不等于确认、草稿有明确所有者、展示不冒充执行事实；但不共享 DOM 组件、像素尺寸 Token，也不为此新增跨端万能展示协议。

### 1.1 本轮包含

- 组件选型、禁止场景、交互生命周期、状态归属、尺寸及扩展边界。
- 独立视觉基础：语义 Token、明暗主题、字体角色、间距、形状、动效、层级与可访问状态。
- 新基础组件、必要的交互模式，以及从公开入口消费它们的组件场景页。
- 新工作台、设置和文件页面的前端交互设计，用明确标识的本地场景数据验证布局、状态和组合。
- 独立浏览器开发入口、类型/静态检查、必要行为回归和真实浏览器视觉及键盘验收。

### 1.2 本轮不包含

- Harness、模型、工具、审批、历史、配置、日志、文件和导出等真实服务接入。
- IPC、Electron preload、主进程改造、凭据存储、数据库、真实网络调用及文件系统读写。
- CLI/TUI 呈现重构、终端输出协议及终端输入改造；现有 `agent:dev` 保持不变。
- 替换生产 `App`、现有页面/组件/样式，迁移生产数据，删除旧实现。
- 完整复刻现有所有设置、PPT 编辑/渲染/放映或所有业务卡片。预览只验证通用 UI 外壳和本地静态内容。
- 新 UI workspace 发布、全局服务容器、插件化组件注册框架、未来后端协议的提前设计。

本地场景数据不是后端实现或真实执行证据。所有模拟保存、审批、进度、取消和错误均须在预览界面标识；不得让用户填写真实 Key，也不能显示暗示真实落盘、真实授权或真实模型执行的成功提示。

## 3. 目录、依赖与样式隔离

以下为新体系落点。U1/U2 已建立 foundations、provider、必要 internal、五个组件、两个模式及独立预览；页面整合和其余组件按 U3/U4 再创建，不预建空目录。所属桌面已归 `app/`，宿主分类历史证据不代替本轮 UI 验收。

```text
app/renderer/src/ui/
  foundations/                 # 新语义 Token、主题、排版、动效与基础样式
  internal/                    # 私有焦点、定位、弹层及其他交互机制
  components/<component>/      # 明确命名的组件入口、契约、局部样式
  patterns/                    # 确认、未保存修改等真实重复模式
  provider/                    # 主题作用域、所属 Portal 与反馈宿主
  styles.css                   # 新体系样式入口
app/renderer/src/ui-preview/
  index.html
  main.tsx                     # 独立入口，不导入旧 main/App
  PreviewApp.tsx               # 场景导航、主题和视口检查
  scenarios/                   # 组件及组合交互场景
  pages/                       # 工作台、设置、文件与内容预览页面
  state/                       # 本地页面控制器、明确具名的展示类型
  fixtures/                    # 固定、非敏感场景数据
vite.ui.config.ts              # 独立 Vite 配置，不引用 Electron 配置
```

依赖方向为 `ui-preview → ui 公开组件/模式入口 → ui 内部机制与基础样式`。页面与场景数据不进入通用组件；`ui` 不反向依赖预览。

- 不新增 `index.ts` 聚合入口。按组件名暴露具名入口；私有实现不是受支持的调用面。
- 新体系不得导入旧 components、app controllers、styles、lib UI 辅助实现、shared 业务协议、cards store、PPT 模型或 `@agent-harness/*`。相同辅助能力需要在新体系内按实际需求实现。
- 不导入旧 `styles.css`、主题安装函数、旧弹层/定位实现，不建立旧 API 兼容包装，不通过全局对象借用旧 Store。
- Token 使用独立 `--ui-*` 命名；样式和主题限定在新根作用域。组件类名采用独立前缀，不借用旧类名。基础元素重置不得泄漏到作用域外。
- Portal 必须挂到所属新 UI 根/模态宿主，继承正确主题；不能默认丢到无主题的 body，再用全局 CSS 补救。
- 预览不得引用旧 renderer 全局类型提供的 `window.desktopApi`；不通过可选调用或假成功回退掩盖依赖。
- 目录不等于封装完成。预览作为外部消费者；依赖约束接入现有静态工具能力，检查实际导入/样式依赖，不用导入次数、文件数量或源码字符串断言代替边界。

### 3.1 仓库根目录按 app / cli 两个宿主分类

采用根级 `app/` 和 `cli/`，不增加 `apps/` 或 `electron/` 包裹层。`app/` 表示当前 Electron 桌面应用，不表示通用 Harness；`cli/` 表示终端宿主。现有 `packages/` 中的通用模块保持独立，不为了“分两类”塞进某个应用。

```text
app/
  main/                       # Electron 入口、平台适配与桌面组合根
  preload/                    # Electron IPC 桥接
  renderer/                   # 保留内部 src/public/HTML 组织
  shared/                     # 仅桌面应用共享协议
cli/
  main.ts                     # 生产 Node 入口，agent / agent:dev 共用执行入口
  commands/                   # 参数、命令与帮助
  terminal/                   # 终端输入、控制器、TUI 与 print/JSONL 呈现
  host/                       # 配置、模型、存储、日志及能力装配
packages/                     # harness/configuration/tools/logs/models 等通用包
```

本次按两个宿主落实职责，不顺带把所有模块拆包，也不直接把整个 `src/` 改名为 `app/`。迁移前后对应关系如下：

| 迁移前内容 | 当前归属及边界 |
| --- | --- |
| `src/main` 的 Electron 启动、窗口、IPC、桌面平台适配 | 归 `app/main`；旧生产 Agent 链路保留，不借目录迁移切换执行实现 |
| `src/preload`、`src/renderer` | 分别归 `app/preload`、`app/renderer`；新 UI 使用本节上方目标路径 |
| `src/shared` | `ipc.ts` 与桌面结果投影 `agent-result-copy.ts` 已迁到 `app/shared`；配置纯契约后续已归 `packages/configuration`，其余会话及领域契约不整目录视为跨宿主公共 API |
| 原 `src/main/agent-host` 的命令、终端投影、模型向导、交互执行 | 分类切片先拆入 CLI；后续已由 `cli/main.ts`、`cli/commands`、`cli/terminal`、`cli/host` 接管，不再以 `development-terminal.ts` 或旧向导路径作为当前落点 |
| 原 `src/main/agent-host` 的装配与 Electron CLI 平台桥接 | CLI 所需装配已归 `cli/host`，通过 configuration/core/models/logs/tools 公开入口接入；旧 Electron CLI 桥接已退出执行链，不代表桌面旧 Agent 已切换 |
| `src/tools`、`src/ppt`、`src/design-system` | 文件工具通用实现已归 `packages/tools`；PPT 与演示内容 design-system 仍按领域职责保留，不为目录整齐批量迁移 |
| `scripts/run-agent.mjs` | 当前为 Node 开发启动器；`agent:dev` 与 `agent` 使用同一 CLI 执行入口，不再启动 Electron CLI 桥接 |

顺序与门槛：

1. 目录分类及终端/平台职责拆分已完成，历史验证见第 12 节；CLI 后续已完成独立 Node 化，当前实施范围与验证限制以 [CLI 方案](cli-terminal.md)为准，不借用旧 Electron 桥接记录证明当前 CLI 行为。
2. U0 契约工作可先推进。U1 所需桌面目录迁移门槛已有第 12 节历史记录；实施时仍须核对当前入口和配置，不以目录已移动替代新 UI 运行证据，不自动重命名共享/领域模块。
3. CLI 配置、凭据、数据目录与终端机制由 CLI 方案拥有，本 UI 计划不重复设计、不回退到 Electron 桥接，也不以明文 Key 或静默回退替代安全存储。
4. 迁移只在对应切片实施时修改源码。桌面切片实际运行入口与构建；CLI 切片实际验证帮助、输入、EOF 等待、取消、恢复和关闭；根命令、调用方与测试同步更新，不以只移动目录验收。

两端只通过所属模块的公开协议共享能力，不相互导入应用私有源码。目录分类不意味着新增 workspace、变更存储格式、迁移生产数据或提前设计后端协议；具体依赖切断与模块落点在实施前核对。

## 4. 使用规则的设计方式

规则分三层：跨组件原则、业务无关的交互模式、单组件契约。规则先于 API 定稿；组件库与场景示例一起验证，不能先堆 API 再补文档。

### 4.1 跨组件原则

1. 上下文优先：字段和区域问题就地表达，不能全部交给全局 Toast。
2. 最小打断：只有必须进入独立上下文时才使用模态；严重度不直接决定载体。
3. 必要信息不得只依赖定时消失或 hover 才可见的内容。
4. 关闭/隐藏不等于确认、拒绝、取消执行或业务完成。
5. 每份状态一个所有者；可推导状态不另存一份。
6. 同类场景一致处理；例外必须具名，说明条件与验证要求。
7. 视觉尺寸服从内容职责；内容越界先考虑替代组件，而非无限放大容器。
8. 任务优先：默认界面展示当前对象、内容、状态和下一步动作，不展示架构说明、开发阶段或验收过程。
9. 渐进披露：低频工具与解释有稳定、具名的入口；主动作、关键错误、审批后果和取消不能为了简洁而隐藏。
10. 文档不是界面：组件职责写在本文件，测试步骤放验收工具；不把开发规范复制成常驻页面正文。

### 4.2 场景决策矩阵

| 用户需求 | 默认方式 | 禁止/升级边界 |
| --- | --- | --- |
| 控件简短补充说明 | Tooltip | 不放必要操作、表单或长说明；重要信息必须在其他可访问位置存在 |
| 非关键、一次性结果 | Toast | 关键失败和必须处理的事项不能只依赖 Toast；可选操作必须有足够操作时间 |
| 字段校验失败 | Field error | 不仅用颜色或 Toast；提交后定位首个错误字段 |
| 当前区域的持续问题 | Alert | 不抢焦点、不因固定计时消失；关闭不代表问题已解决 |
| 应用级持续状态 | Banner | 同时最多一个主 Banner，优先级明确，不承担字段校验 |
| 与锚点关联的轻量交互 | Popover | 复杂编辑/必须决策升级 Dialog；草稿不能因 outside click 无规则丢弃 |
| 简短、对象明确的二次确认 | Popconfirm | 复杂后果、额外输入或高风险确认升级确认 Dialog |
| 独立编辑/重要确认/大内容查看 | Dialog 对应用途 | 不通过大量布尔值拼成任意行为；编辑关闭须经过草稿规则 |
| 执行命令/导航 | Menu | 不替代选值控件 |
| 从选项选择值 | Select | 不替代命令菜单；输入补全按 Combobox/listbox 语义另行实现 |
| 一组对象信息及操作 | Card | 不天然创建实体副本或全局卡片 Store；业务状态机不放基础外壳 |

先完成单选 Select；Combobox/多选不是首轮隐含功能，Slash 补全和复杂模型两页选择不在本轮组件清单中冒充已覆盖。后续需要时单独定义使用契约。

### 4.3 每个组件的必备契约

- 职责、适用条件、禁止场景与替代方式；至少一个正确和一个错误用法说明。
- 内容边界、允许的操作、触发方式。
- 出现、更新、关闭与失效条件；Escape、outside、关闭按钮、取消、卸载的含义。
- 可访问名称、描述、键盘路径、初始焦点、焦点恢复和读屏公告策略。
- 受控/非受控能力、状态归属、异步结果有效性。
- 多实例、嵌套、并发与所属主题/Portal 规则。
- 组件自己的尺寸规格、长内容、溢出和窄窗口处理。
- 强制规则、默认行为、允许配置项和受支持例外；不能把所有内部参数都公开。

首轮组件的使用边界、关闭原因、受控能力、禁用/只读/处理中差异、焦点后备和反馈冲突规则已在第 8.1.1 节定稿。U0 是可实施契约，不代表 U3 组件已实现；U1/U2 的运行与交互证据见第 12.1 节，R1 新界面及复验另见第 12.3 节。

规则和实施证据持续更新到本文相应章节，不另外创建一批重复设计文档。旧样式 README 不作为新体系实现说明。

## 5. 组件、视觉和交互约束

### 5.1 首轮组件范围

- 控件：Button/IconButton、Input/Textarea、Field（标签/帮助/错误关联）、Checkbox/Radio/Switch、Tabs、单选 Select、Menu。
- 反馈：Tooltip、Toast、Alert、Banner、加载/空状态/错误状态的必要呈现。
- 容器与浮层：Dialog（含确认/表单/预览规格）、Popover、Popconfirm、Card 的标题/正文/操作区。
- 必要模式：异步确认、未保存修改离开。模式不直接调用后端，不形成通用服务查找器。

原生控件优先保留原生语义。组件不主动读取业务 Store、不发 IPC/请求、不把业务结果猜测成成功。每个按钮都应执行明确的本地 UI 动作或显式触发场景控制，不能放无响应的“功能按钮”。

### 5.2 视觉与独立尺寸

- 首轮只建立一套新视觉语言及 light/dark 两种模式，不复制 Studio/Catnip 或加载自定义主题；以中性工作面、清晰层级和有限强调色为默认。
- 基础 Token 提供色阶与尺度，语义 Token 表达 surface/text/border/action/status/focus；组件尺寸配方由组件内聚。不同组件不共享一个强制的 `sm/md/lg` 宽高表。
- Tooltip/Toast/Popconfirm 限制内容和宽度；Alert/Banner 跟随所属容器；Menu/Select 的触发器与面板尺寸分开；Card 内边距归组件、外间距归布局。
- Dialog 使用紧凑确认、标准表单、宽内容和全屏预览规格。阶段 U1 定下并记录实际数值；后续不能依靠调用方覆盖内部 width/padding 来形成隐性规格。
- 正文可读文本对比度目标 4.5:1；适用的大文本 3:1；焦点及必要非文本边界按适用 WCAG 要求检查。选中、hover、pressed、键盘 active 分开表达。
- 验证中文、长英文、长路径、换行、200% 缩放、窄窗口、reduced-motion 与 forced-colors；不把浏览器模拟称为 OS 高对比度/真实读屏认证。

### 5.2.1 首版视觉规格与校准规则

采用中性工作面、有限强调色和稳定密度。背景层次、边界与留白优先，不把每个区域包装成 Card；强调色只承担主要动作、选中和焦点。长文本左对齐并限制阅读宽度。关键操作保留文字，图标按钮必须有可访问名称。

以下为首版参考规格及行为基线，不是每种页面的固定尺寸；R1 设置页的实际配方另见第 12.3 节。第 12.1 节颜色保留为历史实现记录，当前风格按第 5.2.2 节修订。修改通过所属 Token 或组件规格完成，不用页面覆盖内部样式；不新增全局「紧凑模式」来掩盖信息架构问题。

| 项目 | 首版建议值或规则 |
| --- | --- |
| 字体角色 | 系统无衬线中文字体；代码与路径使用等宽字体，不依赖旧字体安装函数 |
| 字号 | 辅助信息 12px、控件 14px、正文 14–16px、区块标题 18px、页面标题 24px |
| 行高 | 正文约 1.6，控件和标签约 1.4 |
| 间距尺度 | 4 / 8 / 12 / 16 / 24 / 32px |
| 默认按钮和单行输入高度 | 36px；触摸场景扩大命中区域，命中区域不能相互重叠 |
| 圆角 | 控件 6px；卡片与浮层 10px；不默认使用胶囊形状 |
| 侧栏 | 展开 240px、折叠 64px；窄窗口改为面板切换 |
| 阅读宽度 | 表单最大约 640px，消息最大约 800px |
| Dialog 宽度上限 | 紧凑确认 400px、标准表单 560px、宽内容 960px；全屏预览单独定义 |
| 浮层视口边界 | 一般至少 16px；窄窗口由组件规格降级，不能固定宽度溢出屏幕 |
| 长内容 | 内容区滚动，标题及主要操作保持可达；不产生无意义的双重滚动 |
| 动效 | U1 使用 140ms；reduced-motion 为 0ms；后续动效不承担必要状态语义 |

Token 按基础尺度/色阶、语义、组件配方三层组织。页面消费语义与公开规格，light/dark 分别映射。普通键盘控件保留 U1 的 2px 焦点环及 2px 偏移；Input 使用自身边框与内描边形成连续轮廓，会话输入由整体容器承接焦点，不在 textarea 内重复套框，见 12.4.1。原生模态仍由浏览器 top layer 管理；第 12.3 节保留语义色检查。

### 5.2.2 风格修订：安静的桌面工具，不是展示站

采用「ChatGPT 的输入/对话主线 + Cursor 的任务/产物关联 + IDEA 的工作台层级与渐进披露」。这是本项目的设计取舍，不复制三套界面，也不引入它们的后端能力。来源与版本范围见第 11.1 节。

- **内容优先于外壳**：中性工作面、低饱和分区；主动作采用高对比中性色。焦点、选择及风险仍清晰，不把紫色品牌块、彩色说明框或渐变作为默认视觉中心。
- **分组不等于套卡片**：连接和会话优先列表行；用对齐、间距、细分隔组织。只有独立对象摘要或确需边界的内容才用 Card，不嵌套多层描边容器。
- **不靠缩小文字来变简洁**：保留可读字号、现有控件命中与焦点门槛；设置列表采用工作台密度，对话正文采用阅读密度，不把同一大留白配方套给所有页面。
- **降低控件竞争**：一处任务区突出一个主要动作，其他动作降为中性/文字形式；导航是可识别的行，不是一列高对比按钮。危险色只用于真正有后果的动作或错误。
- **无宣传性排版**：去掉 Interface Lab、英文大写眉题、开发阶段编号和说明性页脚；标题命名对象或任务，不写愿景和教学口号。
- **文案只补足缺口**：字段名已能解释的不再跟一段帮助；正常状态不放 Alert。错误发生时再给问题与修正方法；安全限制在相关输入附近简短常驻。
- **输入作为完整表面**：参照现有项目的会话输入与 Field 配方，只映射新 Token，不导入旧组件/样式。会话编辑面与工具栏共用外框和留白；普通字段焦点不叠加带间隙的第二层描边。去掉编辑面的独立焦点框时，必须由容器显示焦点，并保留按钮/选择器各自的键盘提示。
- **紧凑选择器融入工作面**：工作区与模型选择使用透明背景和透明常驻边框，保留悬停反馈、焦点提示与展开菜单表面；不改变设置表单的 field 配方。浏览器已确认两处默认背景/边框透明，模型键盘切换与工作区展开/Escape 收起可用。

短文案不等于藏信息：图标须有可访问名称，hover 动作也要在 focus-within/键盘路径可达；主要功能不能只靠快捷键或记忆命令发现。


### 5.3 关闭与异步交互

- Dialog 对外提供关闭请求及必要原因，不把同一个 `onClose` 同时当作取消、确认和提交完成。
- 确认只能由显式确认动作触发；Escape/outside/取消不能触发确认。Dialog 具备清晰的关闭/取消路径，草稿保护通过有理由的离开检查实现。
- 表单提交失败保留输入和原位错误；提交成功才结束本次编辑。关闭不暗示撤销已经发出的操作。
- 等待本地演示提交/确认期间，目标和编辑实例必须绑定；取消、卸载、重开后丢弃旧回调，不允许旧结果关闭新窗口。
- 模态背景不可交互、焦点受约束且合理返回；嵌套只由顶层处理 Escape；内部 Select/Menu 的 Portal 必须归属当前 Dialog。
- Tooltip 不接收焦点，不包含交互控件；指针移入提示内容时不能立即消失，键盘可触发并能通过 Escape 隐藏。
- 首轮 Toast：最多显示 3 条，其余排队；同标识消息更新，不按文本猜测身份；无操作的非关键提示默认 5 秒，hover/focus 暂停，有操作提示不自动消失。主题/页面切换不重复公告；卸载清理计时。此处是本项目选择，不是厂商通用标准。
- Toast 消失不设置“已读/已解决”；Alert 是否可关闭由用途决定，不能隐藏尚需修复问题的唯一提示。

### 5.4 公开契约与内部交互机制分工

- Dialog 负责模态语义、标题/描述关联、焦点和关闭请求；异步确认模式负责显式确认及处理中状态；未保存修改模式负责继续编辑或放弃草稿。模式通过窄回调接收页面操作，不解释业务结果。
- Dialog 按确认、表单、预览用途提供规格，不向页面暴露整套焦点栈、层级或定位参数。U0 定稿关闭原因的具名类型、回调含义及各用途默认策略，不把 `onClose` 当作万能结果回调。
- 确认 Dialog 默认不因遮罩点击结束决策；表单关闭统一经过草稿检查；无草稿的内容预览允许 outside 关闭。Escape 和取消不触发确认，破坏性确认不默认获得初始焦点。
- 每次关闭后返回合理触发点；触发点已卸载时，由所属页面提供可解释的后备焦点。嵌套离开确认结束后回到原编辑上下文。
- `internal/` 内聚 Portal 归属、浮层层级、焦点约束/恢复、顶层 Escape、outside 判断和锚点定位。按首个场景需求实现，不预建通用浮层框架；U3 复用并补齐翻转、边界偏移和滚动处理。
- 同一次 Escape 或指针事件只由符合条件的顶层处理，内部 Select/Menu 关闭不能继续关闭 Dialog。模态背景真正不可交互，不能只依靠遮罩或视觉变暗。
- 组件公开面只包含页面需要的内容、值、操作和用途规格；预览不直接导入 `internal/`。文本输入及按钮保留原生语义；按用户对下拉外观的要求，单选 Select 使用自绘触发器/listbox，原生 popover 仅负责 top layer 与轻量关闭，不再渲染浏览器默认 select 列表。

### 5.5 交互底座的实现与依赖决策

- 不引入整套 UI 库，不等于必须手写所有无障碍与弹层机制。U0 按实际首个场景明确：哪些使用原生能力、哪些由新体系内部实现、哪些确需底层依赖；若需要依赖，先记录许可证、公开 API、React 兼容性、主题/Portal 归属及维护取舍。
- 焦点约束与恢复、模态背景隔离、嵌套 Escape、outside 和锚点定位是共同底座，不能由每个组件或页面各写一套。无论采用何种实现，页面只消费新体系公开契约，不直接依赖底层库。
- 不预建通用框架，不因依赖已有大量功能而扩大首轮范围。U2 先验证表单与嵌套确认；U3 再按真实组合需求补齐定位与浮层能力。
- 底座选型以真实浏览器中的焦点、命中、嵌套和卸载行为为依据，不以依赖少或组件代码短作为正确性证据。

## 6. 页面与本地状态设计

独立预览只保留一处低强调但清晰可见的「预览」标记，具名「预览说明」入口解释仅内存、无服务；不在标题、侧栏、字段、Banner、页脚重复同一免责声明。演示 Key 的必要安全限制仍在字段旁可见。场景选择、重置和故障注入已收进显式打开的「验收工具」，与产品内容分层；普通导航不能偷偷重置状态。

| 页面/场景 | 必须完成的本地交互 | 明确不做 |
| --- | --- | --- |
| 工作台壳层 | 侧栏展开/折叠、区域切换、窄窗口布局、明暗模式 | 原生标题栏、系统窗口按钮、Electron 生命周期 |
| 会话工作区 | 本地会话选择及草稿隔离；消息布局；发送在本地追加带演示标记的用户内容；显式场景控制展示空/加载/输出/等待/失败/完成 | 不生成假 AI 回答，不声称真实运行、恢复或取消 |
| 设置与编辑 | 分类导航；一个模型连接外观表单演示字段校验、提交中、成功/失败、脏关闭；主题设置只影响预览 | 不拉取真实模型、不发现远程模型、不保存凭据；Key 字段只接受显式演示值，不要求真实 Key |
| 文件工作区 | 内置文本列表、选择、编辑、dirty、离开取消/放弃；模拟保存成功/失败明确标识 | 不访问磁盘、不声明文件已真实保存；不实现完整文件管理器 |
| 卡片与内容查看 | 信息/待决/结果卡的结构与操作状态；静态内容的 Popover/宽 Dialog/全屏查看 | 不复制旧审批协议、PPT 领域状态、渲染器或导出功能 |
| 反馈组合 | 字段错误、区域 Alert、应用 Banner、Toast 与模态共存 | 不创建持久通知中心或消息后台 |

本地页面类型在 `ui-preview/state` 中具名定义，不复制 Harness Thread/Query/Run、旧 display event 或未来 IPC DTO。展示 phase 只表示当前场景，不是执行事实。

状态归属：组件持有展开/焦点等暂态；页面控制器持有选择、表单草稿、错误、提交阶段；预览根持有主题和跨页面场景。跨区域共享才考虑 store，不建立全局万能 Store。

默认生命周期：下拉/浮层随页面离开清理；本地会话输入草稿按场景会话 ID 在应用本次生命周期保留；文件和表单未保存修改先确认再离开；刷新预览恢复固定初始数据；主题/布局也只保留在本次预览内存中，不读写旧 localStorage。场景重置清理待决操作与计时，不影响旧 UI 或外部数据。

### 6.1 页面信息架构与响应式布局

产品导航、内容、验收工具分层：正常工作区只呈现已实现的页面和当前任务；主题/检查/重置等预览能力放在具名工具入口下，不占常驻宽工具栏。组件目录、样式隔离、原生对照和竞态操作只在主动进入的验收视图出现；不能把整个默认页做成组件展示站，也不为尚未实现的会话/文件功能添加无效入口。

长期工作台采用「稳定侧栏 + 当前任务主区 + 按需产物/详情」，而非固定三栏后台。侧栏用于会话/对象选择；主区属于正在进行的对话或编辑任务。只有主动打开文件、差异或其他产物时才出现详情，窄屏可返回主任务。设置和文件按自身任务组织，不把工作台、配置与验收状态同时挤在一页；具体默认内容见第 6.4、6.5 节。下表是 U4 完整工作台目标，不代表 R1 已实现折叠侧栏或详情面板。

| 可用宽度 | 默认布局 | 验收重点 |
| --- | --- | --- |
| ≥ 1024 CSS px | 侧栏与主内容并列；剩余空间足够才并列详情，否则切为详情视图 | 详情不能挤压主内容至不可读；无空第三栏 |
| 640–1023 CSS px | 侧栏默认折叠；对象列表和详情通过可返回的面板进入 | 导航、选择与返回可达，不强行三栏 |
| < 640 CSS px | 列表、主内容、详情单面板切换，操作允许换行 | 320px 下无页面级非必要横向滚动，草稿和焦点不因切换丢失 |

断点按可用 CSS 宽度判断；200% 缩放后同样进入降级布局。用户手动展开侧栏时仍须满足当前视口约束，不能覆盖主要操作而无退出方式。

R1 仅实现连接设置：桌面使用窄侧栏、两列表格及行内编辑，窄屏改为单行导航、名称/地址两层的连接行；验收面板按可用宽度并列或移到主内容下方。320/768/1280px 与 CSS zoom 的实际观察见第 12.3 节，不用未实现的工作台功能填充页面。

### 6.2 本地展示状态与转换

在 `ui-preview/state` 中定义具名展示类型。会话输入草稿按本地会话 ID 保存；表单和文件的 dirty 从当前内容与本地基线比较得出，提交能力从字段有效性和操作阶段推导，不维护重复布尔状态。

| 场景/事件 | 状态转换与结果 | 禁止行为 |
| --- | --- | --- |
| 表单编辑并提交无效值 | 保持编辑，显示关联字段错误并定位首个错误字段 | 关闭窗口、丢输入或只弹 Toast |
| 表单开始模拟提交 | 绑定目标及编辑实例，进入本地提交中；明确标记未连接服务 | 将提交中显示为真实连接/保存 |
| 当前提交模拟失败 | 回到可编辑状态，保留草稿；字段或区域显示适当错误 | 清理草稿或仅显示短暂错误 |
| 当前提交模拟成功 | 更新该目标的本地演示基线并结束本次编辑 | 暗示凭据已保存或远程连接已验证 |
| 有草稿时请求关闭/导航 | 进入离开确认；继续编辑则保留原对象和草稿，放弃则完成原离开意图 | 在确认前先切换对象，或要求用户重复发起导航 |
| 本地提交中请求取消/关闭 | 先使该操作结果失效，再按 dirty 规则处理离开；保留清晰退出路径 | 把关闭描述为撤销外部操作 |
| 会话选择及发送 | 选择保留各自草稿；非空发送追加带演示标记的用户消息并清空该会话输入 | 自动生成假 AI 回复，或重置其他会话草稿 |
| 文件模拟保存成功/失败 | 成功只更新该内置文本的内存基线；失败保留编辑与 dirty 并就地提示 | 访问磁盘，或显示真实文件落盘成功 |
| 场景控制切换展示 phase | 显式展示预设空/加载/输出/等待/失败/完成，保留演示标记 | 从计时或按钮点击推断真实执行事实 |
| 场景重置 | 恢复固定数据、清理临时资源并使旧结果失效 | 借每次普通导航自动重置掩盖生命周期错误 |

每次本地异步操作绑定目标 ID、编辑实例 ID、操作 ID 和场景重置世代；仅当前匹配结果可更新状态。取消、卸载、切换目标或重开编辑均使旧操作失效，重置推进世代。实际计时器及监听器也须清理，不能只忽略回调而保留资源。

### 6.3 U2 连接表单的固定验收场景

只使用内置连接对象，字段包括显示名称、示例连接地址和显式演示 Key。地址仅按本地格式规则校验，不发请求；Key 只接受公开演示常量 `demo-key`，其他内容就地拒绝，不保存、不记录、不回显为配置。

确定性故障注入保留：在「验收工具」中明确选择本地成功/失败、暂缓/释放及旧结果场景，不依赖随机计时。普通编辑默认直接完成本地示例，不要求选择结果或手动释放；动作使用「保存示例」，不能写成真实连接/凭据保存。活动模态中的验收操作仍归属该模态，不能为操作外部调试面板而解除背景 inert。

本场景完成输入、校验、失败修正、成功结束、脏关闭和旧结果隔离后才扩展组件数量。若页面仍须绕过组件处理焦点、覆盖内部尺寸或直连浮层机制，应先修正契约，再进入 U3。

### 6.4 R1：现有连接场景的默认界面

R1 调整 `PreviewApp.tsx` 与 `ConnectionForm.tsx`，分离说明、重复对象信息及验收控制。下表保留连接编辑的呈现约束；R2 将其迁入设置的模型分类，不再让连接管理充当应用首页：

| 区域 | 默认保留 | 移出默认视图或取消 |
| --- | --- | --- |

### 6.5 后续工作台：让任务状态可见，而非让内部实现可见

此节约束 U4 的方向，不计入 R1 实施范围：

- **空会话**：输入区与明确的新建/选择入口；最多必要的短引导，不用功能介绍填空，也不自动播放假 AI 回复。
- **会话进行中**：正文为主，输入区位置稳定；当前模型/已安装能力在相关入口查看，不在每条消息重复列运行配置。切会话保留各自草稿。
- **工具执行**：简洁的进行/完成/失败摘要；输出和参数按需展开。待审批的目标、影响和允许/拒绝动作必须直接可见；不能把权限决策埋在折叠日志里。
- **结果审阅**：先给结果与必要动作，通过「查看内容/变更」进入文件或产物视图；不把原始日志堆进对话，也不默认打开空详情栏。文件、图表、PPT 等能力均按已安装能力出现，不反向规定内核。
- **设置/工具窗口**：从稳定入口打开，用完回到任务；不为降低字数将所有功能藏进图标或命令面板。预览只用显式场景数据，实际结果仍须等后续公开协议接入。

### 8.1.1 第一轮定稿：U0–U2 契约与实现决策

本轮按 U0 → U1 → U2 实施，不接真实服务、不替换生产 UI。U0 覆盖首轮组件清单的使用规则；U1/U2 只实现纵向表单实际需要的 Button、Input、Field、Alert、Dialog 和两个模式，其余组件留在 U3，不能把契约定稿算作组件已实现。

**交互底座**：采用浏览器原生 `dialog.showModal()`、原生表单控件和 React Portal，不新增依赖。原生模态负责 top layer、背景 inert 和焦点导航；内部薄层统一补齐首尾 Tab/Shift+Tab 包裹，并管理受控关闭、所属 Portal、模态顺序、关闭原因和后备焦点。取消事件阻止默认关闭并只交给顶层；不通过 `open` 属性冒充模态，也不在页面重复实现焦点栈。嵌套 Portal 挂在当前 Dialog 内并继承主题。后续锚点定位只在 U3 有真实需求时补齐。

选择依据：[MDN dialog](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog) 与 [WAI-ARIA 模态模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。原生能力减少自建无障碍机制，但不免除真实浏览器的键盘、嵌套、命中和卸载验证；不为不支持 `showModal()` 的环境提供假模态降级。

共同契约：

- 组合控件的 `value/checked/open` 由调用方拥有，变更请求与结果分离；不混用同一属性的受控和非受控模式。基础 Input 保留原生受控/非受控属性及 DOM 行为，本轮表单全部受控。组件只拥有焦点、hover 等暂态；页面拥有草稿、选择与业务阶段。
- `disabled` 表示不可操作且退出 Tab；`readOnly` 仅用于文本控件，保留选择/复制/Tab，不伪装禁用；`busy` 显示处理中语义并阻止重复提交，取消和关闭不因此消失。按钮文字由调用方明确提供，不根据 Promise 猜测成功。
- 组件必须有可访问名称；Field 通过 `id`、`htmlFor`、`aria-describedby` 和 `aria-invalid` 关联，错误不逐键抢读屏。首次无效提交由页面聚焦首错；区域错误使用持续 Alert，不以 Toast 替代。
- 关闭请求是 `escape | outside | close-button | cancel`，不包含成功/确认；成功由拥有操作的页面提交后显式结束编辑。卸载是清理，不派发用户决定。Dialog 触发点消失时由页面提供 `fallbackFocusRef`，回到仍有效的导航/标题，不随意落到 body。
- 标准表单 outside/Escape/取消/关闭均走同一离开检查；确认 Dialog 禁止 outside 决策，初始焦点为非破坏性动作；内容预览允许 outside。一次事件只处理顶层。Dialog 使用确认 400px、表单 560px、宽内容 960px、全屏四种用途规格，视口边距 16px，正文可滚动、操作可达。
- 提示没有交互生命周期；有操作、草稿或强制决定时必须升级载体。反馈去重按显式身份，不按文本。关键错误始终有原位文本；`announce` 由拥有状态的页面选择，静态提示默认不公告。

| 组件/模式 | 具名公开契约、内容及键盘 | 正确用法 / 禁止用法与替代 |
| --- | --- | --- |
| Button / IconButton | 原生按钮；`tone`、`busy`；默认 `type=button`；Enter/Space 原生激活；IconButton 必须 `label`，不接长正文 | 明确“模拟提交” / 不把导航伪装按钮，也不只用颜色说明破坏性动作 |
| Input / Textarea | 原生文本控件属性及 ref；受控组合；保留输入法、选择、readOnly；Textarea 不拦截 Enter 为提交 | Field 中编辑 / 不作为富文本或命令菜单 |
| Field | `id,label,hint,error,required` 与 render-prop 关联控件；帮助和错误可共存；不持有输入值 | 字段关联错误 / 不仅 Toast，不用 placeholder 代替 label |
| Checkbox / Radio / Switch | `checked,onCheckedChange`；Radio 以同名原生组表达单选；Switch 有稳定标签和开关语义；不支持 readOnly | 同意条款/选值/即时开关各用其语义 / 多选不使用 Radio，提交动作不使用 Switch |
| Tabs | `value,onValueChange,items`；tablist/tab/tabpanel 关联；方向键移动、Home/End、手动 Enter/Space 激活；卸载规则由页面明确 | 同一区域视图 / 不取代路由导航；切换不隐式丢草稿 |
| Menu | `open,onOpenChange,items,onAction`；仅命令/导航，roving focus、方向键/Home/End，Enter/Space 执行；Escape/outside 返回触发点 | “重命名/移除” / 选值改 Select，表单改 Dialog |

| Popover | `open,onOpenChange,trigger,children`；关联轻量内容；交互内容具名、Escape/outside 关闭且返回触发点；复杂内容升级 Dialog | 轻量说明/操作 / 不无保护承载草稿或强制决定 |
| Popconfirm | `open,onRequestClose,onConfirm,pending`；对象明确、短文本、两个显式动作；Escape/outside 仅取消；初始焦点非破坏性 | 简短可解释确认 / 多段后果、额外输入或高风险升级确认 Dialog |
| Tooltip | `content,children`，简短纯文本；hover/focus 出现、Escape 隐藏、指针可移入；本身不可聚焦；卸载清理延时 | 非必需补充 / 操作改 Popover，重要说明写入页面 |
| Toast | 以 `id` 更新、显式 dismiss；非关键结果最多 3 条，其余排队；无操作 5 秒，hover/focus 暂停，有操作不超时；polite 新增公告 | 临时次要结果 / 必须处理错误改 Alert，不用文本推断身份 |
| Alert | `title,children,tone,announce`；持续区域文本，无默认关闭；静态默认 off，当前失败 assertive、完成提示 polite | 表单失败保留 / 不自动消失、不用来承载字段校验 |
| Banner | 具名 `id,priority,scope` 与显式解决条件；阻断当前操作优先，再按影响范围和稳定 id；最多一条主 Banner；不因新到达覆盖旧项 | 应用级持续状态 / 字段问题改 Field，局部问题改 Alert |
| Loading / Empty / Error | 具名标题、说明与可选明确操作；加载 `aria-busy`，错误可重试但不自动发请求；空态不是失败 | 区域呈现 / 不把计时结束当执行完成，不吞掉旧可用内容 |
| Dialog | `open,purpose,title,description,onRequestClose,initialFocusRef,fallbackFocusRef,children,footer`；内容具名，取消不提交；原生模态与内部所属宿主 | 独立表单/确认/内容查看 / 不覆盖内部尺寸、直连焦点栈或用一个 onClose 表示所有结果 |
| Card | `title,description,children,actions`，无状态容器；标题级别与页面层级匹配；动作是独立控件 | 对象摘要 / 不天然可点击、不持有实体副本或接管业务状态机 |
| 异步确认模式 | `ConfirmDialog` 只由显式确认调用 `onConfirm(signal)`；处理中禁止重复、保留取消；关闭/卸载中止本地等待，旧结果不得修改新实例；失败留原位 | 受控确认 / 不在 setup/mount 执行，不把关闭视为撤销外部效果 |
| 未保存修改模式 | `UnsavedChangesDialog` 接受 `onContinueEditing,onDiscard`；继续编辑保留草稿，放弃后执行原离开意图；不解释业务结果 | 脏关闭、目标/页面切换 / 不先切目标再问、不要求重复导航 |

U2 固定场景使用两项内置 `.invalid` 地址连接；仅名称和地址可成为内存演示基线。演示 Key 只接受 `demo-key`，其他输入立即拒绝且不存入状态/队列/错误文本，成功后也不保留 Key。提交在开始时绑定目标、编辑实例、操作和重置世代；手动暂缓/释放替代随机计时。退出使等待失效并解除回调，保留的旧结果场景只含安全身份元数据，用来实际投递过期完成事件验证隔离，不保留失效闭包或秘密输入。

导航离开与普通关闭共享草稿规则；请求取消本地等待后若选择继续编辑，保持草稿但不复活旧操作。场景重置/卸载释放等待资源并推进世代；预览不使用 localStorage，不做真实 HTTP/IPC/文件调用。首轮验收覆盖两个对象、失败修正、重复提交、离开两分支、嵌套 Escape、取消重开和 reset 后释放旧结果。
