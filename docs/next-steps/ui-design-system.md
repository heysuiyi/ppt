# 独立页面 UI 设计体系：使用规则、组件与场景执行方案

[返回计划目录](README.md) · [项目整体规划](../project-plan.md)

状态：根级 app/cli 宿主分类切片已完成本地验收，目录与职责迁移及验证记录见第 3.1、12 节。UI 的 U0 契约核对及 U1–U5 实施与交互验收仍待执行；目录迁移不等于新 UI 已实现，不接入新后端，也不切换生产执行链。

## 1. 目标与范围

本轮建设一套能够独立运行、具有清晰使用规则的页面 UI 体系。采用新目录、新实现和独立预览入口；现有生产 UI 保持原样。先完成组件与页面交互，再在下一步另行设计后端交互和生产迁移。

完成标准不是“列出组件”或“展示静态效果”，而是：面对同一场景，可以依据规则选出组件；组件默认行为符合契约；页面能通过本地受控状态演示完整交互；规则中的错误用法有明确替代方式。

### 1.1 本轮包含

- 组件选型、禁止场景、交互生命周期、状态归属、尺寸及扩展边界。
- 独立视觉基础：语义 Token、明暗主题、字体角色、间距、形状、动效、层级与可访问状态。
- 新基础组件、必要的交互模式，以及从公开入口消费它们的组件场景页。
- 新工作台、设置和文件页面的前端交互设计，用明确标识的本地场景数据验证布局、状态和组合。
- 独立浏览器开发入口、类型/静态检查、必要行为回归和真实浏览器视觉及键盘验收。

### 1.2 本轮不包含

- Harness、模型、工具、审批、历史、配置、日志、文件和导出等真实服务接入。
- IPC、Electron preload、主进程改造、凭据存储、数据库、真实网络调用及文件系统读写。
- CLI/TUI 呈现重构、终端输出协议及终端输入改造；现有 `agent:dev` 保持不变。
- 替换生产 `App`、现有页面/组件/样式，迁移生产数据，删除旧实现。
- 完整复刻现有所有设置、PPT 编辑/渲染/放映或所有业务卡片。预览只验证通用 UI 外壳和本地静态内容。
- 新 UI workspace 发布、全局服务容器、插件化组件注册框架、未来后端协议的提前设计。

本地场景数据不是后端实现或真实执行证据。所有模拟保存、审批、进度、取消和错误均须在预览界面标识；不得让用户填写真实 Key，也不能显示暗示真实落盘、真实授权或真实模型执行的成功提示。

## 3. 目录、依赖与样式隔离

以下为新 UI 的计划落点，组件和预览入口尚不存在；所属桌面目录已从 `src/` 迁到 `app/`。按阶段创建真实实现，不预建空文件。宿主分类与 UI 实施分开验收，不将目标路径描述为已完成组件。

```text
app/renderer/src/ui/
  foundations/                 # 新语义 Token、主题、排版、动效与基础样式
  internal/                    # 私有焦点、定位、弹层及其他交互机制
  components/<component>/      # 明确命名的组件入口、契约、局部样式
  patterns/                    # 确认、未保存修改等真实重复模式
  provider/                    # 主题作用域、所属 Portal 与反馈宿主
  styles.css                   # 新体系样式入口
app/renderer/src/ui-preview/
  index.html
  main.tsx                     # 独立入口，不导入旧 main/App
  PreviewApp.tsx               # 场景导航、主题和视口检查
  scenarios/                   # 组件及组合交互场景
  pages/                       # 工作台、设置、文件与内容预览页面
  state/                       # 本地页面控制器、明确具名的展示类型
  fixtures/                    # 固定、非敏感场景数据
vite.ui.config.ts              # 独立 Vite 配置，不引用 Electron 配置
```

依赖方向为 `ui-preview → ui 公开组件/模式入口 → ui 内部机制与基础样式`。页面与场景数据不进入通用组件；`ui` 不反向依赖预览。

- 不新增 `index.ts` 聚合入口。按组件名暴露具名入口；私有实现不是受支持的调用面。
- 新体系不得导入旧 components、app controllers、styles、lib UI 辅助实现、shared 业务协议、cards store、PPT 模型或 `@agent-harness/*`。相同辅助能力需要在新体系内按实际需求实现。
- 不导入旧 `styles.css`、主题安装函数、旧弹层/定位实现，不建立旧 API 兼容包装，不通过全局对象借用旧 Store。
- Token 使用独立 `--ui-*` 命名；样式和主题限定在新根作用域。组件类名采用独立前缀，不借用旧类名。基础元素重置不得泄漏到作用域外。
- Portal 必须挂到所属新 UI 根/模态宿主，继承正确主题；不能默认丢到无主题的 body，再用全局 CSS 补救。
- 预览不得引用旧 renderer 全局类型提供的 `window.desktopApi`；不通过可选调用或假成功回退掩盖依赖。
- 目录不等于封装完成。预览作为外部消费者；依赖约束接入现有静态工具能力，检查实际导入/样式依赖，不用导入次数、文件数量或源码字符串断言代替边界。

### 3.1 仓库根目录按 app / cli 两个宿主分类

采用根级 `app/` 和 `cli/`，不增加 `apps/` 或 `electron/` 包裹层。`app/` 表示当前 Electron 桌面应用，不表示通用 Harness；`cli/` 表示终端宿主。现有 `packages/` 中的通用模块保持独立，不为了“分两类”塞进某个应用。

```text
app/
  main/                       # Electron 入口、平台适配与桌面组合根
  preload/                    # Electron IPC 桥接
  renderer/                   # 保留内部 src/public/HTML 组织
  shared/                     # 仅桌面应用共享协议
cli/
  commands/                   # 已迁移参数、命令及公开终端投影
  configuration/              # 已迁移模型配置向导；借用注入的配置管理端口
  development-terminal.ts     # 输入队列、会话循环、EOF/取消/恢复与窄平台契约
packages/                     # 现有 harness/models/logs；不提前新增空包
```

本次按两个宿主落实职责，不顺带把所有模块拆包，也不直接把整个 `src/` 改名为 `app/`。迁移前后对应关系如下：

| 迁移前内容 | 当前归属及边界 |
| --- | --- |
| `src/main` 的 Electron 启动、窗口、IPC、桌面平台适配 | 归 `app/main`；旧生产 Agent 链路保留，不借目录迁移切换执行实现 |
| `src/preload`、`src/renderer` | 分别归 `app/preload`、`app/renderer`；新 UI 使用本节上方目标路径 |
| `src/shared` | `ipc.ts` 与桌面结果投影 `agent-result-copy.ts` 已迁到 `app/shared`；其他配置和领域契约暂留原处，不整目录视为跨宿主公共 API |
| `src/main/agent-host` 的命令、终端投影、模型向导、交互执行 | 已拆到 `cli/commands`、`cli/configuration`、`cli/development-terminal.ts`；不直接依赖 app 源码，也不使用 Electron |
| `src/main/agent-host` 的装配、模型配置、存储、Electron 生命周期和父子 IPC | 归 `app/main/agent-host`；`development-runner.ts` 是实际平台桥接，不是旧 API 兼容转发；借窄端口驱动 CLI 流程 |
| `src/tools`、`src/ppt`、`src/design-system` | 不是两个宿主本身，暂保留当前位置；共享或领域模块的最终迁移另按真实依赖决定，不为目录整齐批量建包 |
| `scripts/run-agent.mjs` | 保留实际 Node 启动 Electron 桥接职责，构建输入已改为 `app/main/agent-host/development-runner.ts`；纯 Node CLI 实现后再删除失效平台路径 |

顺序与门槛：

1. 当前已落实目录分类及终端/平台职责拆分，验证结果见第 12 节；CLI 运行时仍借用 Electron，不等于纯 Node 独立。
2. U0 契约工作可先推进。U1 前的桌面目录迁移切片须通过构建、类型检查、行为回归与真实入口烟测；不以目录已移动替代运行证据，不自动重命名共享/领域模块。
3. CLI 的纯 Node 化另行设计配置、凭据、数据目录及现有 Electron 适配的替代边界；不以明文 Key 或静默回退替代 `safeStorage`。UI U1 不等待 CLI 全部独立完成。
4. 迁移只在对应切片实施时修改源码。桌面切片实际运行入口与构建；CLI 切片实际验证帮助、输入、EOF 等待、取消、恢复和关闭；根命令、调用方与测试同步更新，不以只移动目录验收。

两端只通过所属模块的公开协议共享能力，不相互导入应用私有源码。目录分类不意味着新增 workspace、变更存储格式、迁移生产数据或提前设计后端协议；具体依赖切断与模块落点在实施前核对。

## 4. 使用规则的设计方式

规则分三层：跨组件原则、业务无关的交互模式、单组件契约。规则先于 API 定稿；组件库与场景示例一起验证，不能先堆 API 再补文档。

### 4.1 跨组件原则

1. 上下文优先：字段和区域问题就地表达，不能全部交给全局 Toast。
2. 最小打断：只有必须进入独立上下文时才使用模态；严重度不直接决定载体。
3. 必要信息不得只依赖定时消失或 hover 才可见的内容。
4. 关闭/隐藏不等于确认、拒绝、取消执行或业务完成。
5. 每份状态一个所有者；可推导状态不另存一份。
6. 同类场景一致处理；例外必须具名，说明条件与验证要求。
7. 视觉尺寸服从内容职责；内容越界先考虑替代组件，而非无限放大容器。

### 4.2 场景决策矩阵

| 用户需求 | 默认方式 | 禁止/升级边界 |
| --- | --- | --- |
| 控件简短补充说明 | Tooltip | 不放必要操作、表单或长说明；重要信息必须在其他可访问位置存在 |
| 非关键、一次性结果 | Toast | 关键失败和必须处理的事项不能只依赖 Toast；可选操作必须有足够操作时间 |
| 字段校验失败 | Field error | 不仅用颜色或 Toast；提交后定位首个错误字段 |
| 当前区域的持续问题 | Alert | 不抢焦点、不因固定计时消失；关闭不代表问题已解决 |
| 应用级持续状态 | Banner | 同时最多一个主 Banner，优先级明确，不承担字段校验 |
| 与锚点关联的轻量交互 | Popover | 复杂编辑/必须决策升级 Dialog；草稿不能因 outside click 无规则丢弃 |
| 简短、对象明确的二次确认 | Popconfirm | 复杂后果、额外输入或高风险确认升级确认 Dialog |
| 独立编辑/重要确认/大内容查看 | Dialog 对应用途 | 不通过大量布尔值拼成任意行为；编辑关闭须经过草稿规则 |
| 执行命令/导航 | Menu | 不替代选值控件 |
| 从选项选择值 | Select | 不替代命令菜单；输入补全按 Combobox/listbox 语义另行实现 |
| 一组对象信息及操作 | Card | 不天然创建实体副本或全局卡片 Store；业务状态机不放基础外壳 |

先完成单选 Select；Combobox/多选不是首轮隐含功能，Slash 补全和复杂模型两页选择不在本轮组件清单中冒充已覆盖。后续需要时单独定义使用契约。

### 4.3 每个组件的必备契约

- 职责、适用条件、禁止场景与替代方式；至少一个正确和一个错误用法说明。
- 内容边界、允许的操作、触发方式。
- 出现、更新、关闭与失效条件；Escape、outside、关闭按钮、取消、卸载的含义。
- 可访问名称、描述、键盘路径、初始焦点、焦点恢复和读屏公告策略。
- 受控/非受控能力、状态归属、异步结果有效性。
- 多实例、嵌套、并发与所属主题/Portal 规则。
- 组件自己的尺寸规格、长内容、溢出和窄窗口处理。
- 强制规则、默认行为、允许配置项和受支持例外；不能把所有内部参数都公开。

规则和实施证据持续更新到本文相应章节，不另外创建一批重复设计文档。旧样式 README 不作为新体系实现说明。

## 5. 组件、视觉和交互约束

### 5.1 首轮组件范围

- 控件：Button/IconButton、Input/Textarea、Field（标签/帮助/错误关联）、Checkbox/Radio/Switch、Tabs、单选 Select、Menu。
- 反馈：Tooltip、Toast、Alert、Banner、加载/空状态/错误状态的必要呈现。
- 容器与浮层：Dialog（含确认/表单/预览规格）、Popover、Popconfirm、Card 的标题/正文/操作区。
- 必要模式：异步确认、未保存修改离开。模式不直接调用后端，不形成通用服务查找器。

原生控件优先保留原生语义。组件不主动读取业务 Store、不发 IPC/请求、不把业务结果猜测成成功。每个按钮都应执行明确的本地 UI 动作或显式触发场景控制，不能放无响应的“功能按钮”。

### 5.2 视觉与独立尺寸

- 首轮只建立一套新视觉语言及 light/dark 两种模式，不复制 Studio/Catnip 或加载自定义主题；以中性工作面、清晰层级和有限强调色为默认。
- 基础 Token 提供色阶与尺度，语义 Token 表达 surface/text/border/action/status/focus；组件尺寸配方由组件内聚。不同组件不共享一个强制的 `sm/md/lg` 宽高表。
- Tooltip/Toast/Popconfirm 限制内容和宽度；Alert/Banner 跟随所属容器；Menu/Select 的触发器与面板尺寸分开；Card 内边距归组件、外间距归布局。
- Dialog 使用紧凑确认、标准表单、宽内容和全屏预览规格。阶段 U1 定下并记录实际数值；后续不能依靠调用方覆盖内部 width/padding 来形成隐性规格。
- 正文可读文本对比度目标 4.5:1；适用的大文本 3:1；焦点及必要非文本边界按适用 WCAG 要求检查。选中、hover、pressed、键盘 active 分开表达。
- 验证中文、长英文、长路径、换行、200% 缩放、窄窗口、reduced-motion 与 forced-colors；不把浏览器模拟称为 OS 高对比度/真实读屏认证。

### 5.2.1 首版视觉规格与校准规则

采用中性工作面、有限强调色和稳定密度。背景层次、边界与留白优先，不把每个区域包装成 Card；强调色只承担主要动作、选中和焦点。长文本左对齐并限制阅读宽度。关键操作保留文字，图标按钮必须有可访问名称。

以下是 U1 的实施起点，不是已验证的视觉结果。U1 必须用实际页面校准并记录最终值；后续修改通过所属 Token 或组件规格完成，不用页面覆盖内部样式。首轮不增加全局紧凑模式。

| 项目 | 首版建议值或规则 |
| --- | --- |
| 字体角色 | 系统无衬线中文字体；代码与路径使用等宽字体，不依赖旧字体安装函数 |
| 字号 | 辅助信息 12px、控件 14px、正文 14–16px、区块标题 18px、页面标题 24px |
| 行高 | 正文约 1.6，控件和标签约 1.4 |
| 间距尺度 | 4 / 8 / 12 / 16 / 24 / 32px |
| 默认按钮和单行输入高度 | 36px；触摸场景扩大命中区域，命中区域不能相互重叠 |
| 圆角 | 控件 6px；卡片与浮层 10px；不默认使用胶囊形状 |
| 侧栏 | 展开 240px、折叠 64px；窄窗口改为面板切换 |
| 阅读宽度 | 表单最大约 640px，消息最大约 800px |
| Dialog 宽度上限 | 紧凑确认 400px、标准表单 560px、宽内容 960px；全屏预览单独定义 |
| 浮层视口边界 | 一般至少 16px；窄窗口由组件规格降级，不能固定宽度溢出屏幕 |
| 长内容 | 内容区滚动，标题及主要操作保持可达；不产生无意义的双重滚动 |
| 动效 | 约 120–180ms；reduced-motion 下移除非必要过渡 |

Token 按基础尺度/色阶、语义、组件配方三层组织。页面消费语义与公开规格，不直接选基础色阶；light/dark 切换语义映射，不做简单颜色反转。U1 还须明确各语义色、焦点环及层级数值并检查对比度，本表不能代替颜色与状态验收。

### 5.3 关闭与异步交互

- Dialog 对外提供关闭请求及必要原因，不把同一个 `onClose` 同时当作取消、确认和提交完成。
- 确认只能由显式确认动作触发；Escape/outside/取消不能触发确认。Dialog 具备清晰的关闭/取消路径，草稿保护通过有理由的离开检查实现。
- 表单提交失败保留输入和原位错误；提交成功才结束本次编辑。关闭不暗示撤销已经发出的操作。
- 等待本地演示提交/确认期间，目标和编辑实例必须绑定；取消、卸载、重开后丢弃旧回调，不允许旧结果关闭新窗口。
- 模态背景不可交互、焦点受约束且合理返回；嵌套只由顶层处理 Escape；内部 Select/Menu 的 Portal 必须归属当前 Dialog。
- Tooltip 不接收焦点，不包含交互控件；指针移入提示内容时不能立即消失，键盘可触发并能通过 Escape 隐藏。
- 首轮 Toast：最多显示 3 条，其余排队；同标识消息更新，不按文本猜测身份；无操作的非关键提示默认 5 秒，hover/focus 暂停，有操作提示不自动消失。主题/页面切换不重复公告；卸载清理计时。此处是本项目选择，不是厂商通用标准。
- Toast 消失不设置“已读/已解决”；Alert 是否可关闭由用途决定，不能隐藏尚需修复问题的唯一提示。

### 5.4 公开契约与内部交互机制分工

- Dialog 负责模态语义、标题/描述关联、焦点和关闭请求；异步确认模式负责显式确认及处理中状态；未保存修改模式负责继续编辑或放弃草稿。模式通过窄回调接收页面操作，不解释业务结果。
- Dialog 按确认、表单、预览用途提供规格，不向页面暴露整套焦点栈、层级或定位参数。U0 定稿关闭原因的具名类型、回调含义及各用途默认策略，不把 `onClose` 当作万能结果回调。
- 确认 Dialog 默认不因遮罩点击结束决策；表单关闭统一经过草稿检查；无草稿的内容预览允许 outside 关闭。Escape 和取消不触发确认，破坏性确认不默认获得初始焦点。
- 每次关闭后返回合理触发点；触发点已卸载时，由所属页面提供可解释的后备焦点。嵌套离开确认结束后回到原编辑上下文。
- `internal/` 内聚 Portal 归属、浮层层级、焦点约束/恢复、顶层 Escape、outside 判断和锚点定位。按首个场景需求实现，不预建通用浮层框架；U3 复用并补齐翻转、边界偏移和滚动处理。
- 同一次 Escape 或指针事件只由符合条件的顶层处理，内部 Select/Menu 关闭不能继续关闭 Dialog。模态背景真正不可交互，不能只依靠遮罩或视觉变暗。
- 组件公开面只包含页面需要的内容、值、操作和用途规格；预览不直接导入 `internal/`。原生语义能够满足时优先使用原生控件，不为统一外观重写全部键盘行为。

## 6. 页面与本地状态设计

预览根部始终显示“UI 预览 / 本地演示，不连接后端”，并提供独立场景选择和重置入口。场景切换与正常页面导航区分，不能通过每次重置掩盖页面生命周期问题。

| 页面/场景 | 必须完成的本地交互 | 明确不做 |
| --- | --- | --- |
| 工作台壳层 | 侧栏展开/折叠、区域切换、窄窗口布局、明暗模式 | 原生标题栏、系统窗口按钮、Electron 生命周期 |
| 会话工作区 | 本地会话选择及草稿隔离；消息布局；发送在本地追加带演示标记的用户内容；显式场景控制展示空/加载/输出/等待/失败/完成 | 不生成假 AI 回答，不声称真实运行、恢复或取消 |
| 设置与编辑 | 分类导航；一个模型连接外观表单演示字段校验、提交中、成功/失败、脏关闭；主题设置只影响预览 | 不拉取真实模型、不发现远程模型、不保存凭据；Key 字段只接受显式演示值，不要求真实 Key |
| 文件工作区 | 内置文本列表、选择、编辑、dirty、离开取消/放弃；模拟保存成功/失败明确标识 | 不访问磁盘、不声明文件已真实保存；不实现完整文件管理器 |
| 卡片与内容查看 | 信息/待决/结果卡的结构与操作状态；静态内容的 Popover/宽 Dialog/全屏查看 | 不复制旧审批协议、PPT 领域状态、渲染器或导出功能 |
| 反馈组合 | 字段错误、区域 Alert、应用 Banner、Toast 与模态共存 | 不创建持久通知中心或消息后台 |

本地页面类型在 `ui-preview/state` 中具名定义，不复制 Harness Thread/Query/Run、旧 display event 或未来 IPC DTO。展示 phase 只表示当前场景，不是执行事实。

状态归属：组件持有展开/焦点等暂态；页面控制器持有选择、表单草稿、错误、提交阶段；预览根持有主题和跨页面场景。跨区域共享才考虑 store，不建立全局万能 Store。

默认生命周期：下拉/浮层随页面离开清理；本地会话输入草稿按场景会话 ID 在应用本次生命周期保留；文件和表单未保存修改先确认再离开；刷新预览恢复固定初始数据；主题/布局也只保留在本次预览内存中，不读写旧 localStorage。场景重置清理待决操作与计时，不影响旧 UI 或外部数据。

### 6.1 页面信息架构与响应式布局

预览工具与产品导航分离：预览工具栏放演示标识、主题、场景选择和重置；产品页面导航只放工作台、文件和设置。组件、反馈组合、浮层嵌套、布局及可访问边界放在独立验收场景中，不伪装成生产功能入口。

工作台采用“侧栏 + 当前对象标题/状态/操作 + 主内容 + 按需详情”。侧栏承载产品导航和当前页面对象列表；输入区属于会话主内容。详情只在查看具体对象时出现，不默认保留空第三栏。设置主内容遵循表单阅读宽度，文件主内容显示内置文本编辑区及 dirty 标记。

| 可用宽度 | 默认布局 | 验收重点 |
| --- | --- | --- |
| ≥ 1024 CSS px | 侧栏与主内容并列；剩余空间足够才并列详情，否则切为详情视图 | 详情不能挤压主内容至不可读；无空第三栏 |
| 640–1023 CSS px | 侧栏默认折叠；对象列表和详情通过可返回的面板进入 | 导航、选择与返回可达，不强行三栏 |
| < 640 CSS px | 列表、主内容、详情单面板切换，操作允许换行 | 320px 下无页面级非必要横向滚动，草稿和焦点不因切换丢失 |

断点按可用 CSS 宽度判断；200% 缩放后同样进入降级布局。用户手动展开侧栏时仍须满足当前视口约束，不能覆盖主要操作而无退出方式。

### 6.2 本地展示状态与转换

在 `ui-preview/state` 中定义具名展示类型。会话输入草稿按本地会话 ID 保存；表单和文件的 dirty 从当前内容与本地基线比较得出，提交能力从字段有效性和操作阶段推导，不维护重复布尔状态。

| 场景/事件 | 状态转换与结果 | 禁止行为 |
| --- | --- | --- |
| 表单编辑并提交无效值 | 保持编辑，显示关联字段错误并定位首个错误字段 | 关闭窗口、丢输入或只弹 Toast |
| 表单开始模拟提交 | 绑定目标及编辑实例，进入本地提交中；明确标记未连接服务 | 将提交中显示为真实连接/保存 |
| 当前提交模拟失败 | 回到可编辑状态，保留草稿；字段或区域显示适当错误 | 清理草稿或仅显示短暂错误 |
| 当前提交模拟成功 | 更新该目标的本地演示基线并结束本次编辑 | 暗示凭据已保存或远程连接已验证 |
| 有草稿时请求关闭/导航 | 进入离开确认；继续编辑则保留原对象和草稿，放弃则完成原离开意图 | 在确认前先切换对象，或要求用户重复发起导航 |
| 本地提交中请求取消/关闭 | 先使该操作结果失效，再按 dirty 规则处理离开；保留清晰退出路径 | 把关闭描述为撤销外部操作 |
| 会话选择及发送 | 选择保留各自草稿；非空发送追加带演示标记的用户消息并清空该会话输入 | 自动生成假 AI 回复，或重置其他会话草稿 |
| 文件模拟保存成功/失败 | 成功只更新该内置文本的内存基线；失败保留编辑与 dirty 并就地提示 | 访问磁盘，或显示真实文件落盘成功 |
| 场景控制切换展示 phase | 显式展示预设空/加载/输出/等待/失败/完成，保留演示标记 | 从计时或按钮点击推断真实执行事实 |
| 场景重置 | 恢复固定数据、清理临时资源并使旧结果失效 | 借每次普通导航自动重置掩盖生命周期错误 |

每次本地异步操作绑定目标 ID、编辑实例 ID、操作 ID 和场景重置世代；仅当前匹配结果可更新状态。取消、卸载、切换目标或重开编辑均使旧操作失效，重置推进世代。实际计时器及监听器也须清理，不能只忽略回调而保留资源。

### 6.3 U2 连接表单的固定验收场景

只使用内置连接对象，字段包括显示名称、示例连接地址和显式演示 Key。地址仅按本地格式规则校验，不发请求；Key 只接受公开演示常量 `demo-key`，其他内容就地拒绝，不保存、不记录、不回显为配置。

场景控制明确选择“本地成功”或“本地失败”，并支持暂缓完成与释放旧结果，以验证重开和取消竞态，不依赖随机失败或碰运气计时。提交按钮标记模拟动作，取消保留退出路径。

本场景完成输入、校验、失败修正、成功结束、脏关闭和旧结果隔离后才扩展组件数量。若页面仍须绕过组件处理焦点、覆盖内部尺寸或直连浮层机制，应先修正契约，再进入 U3。

## 7. 独立开发、检查与产物

采用现有 React/Vite 工具链的独立浏览器入口，不引入 Storybook 或全套 UI 库作为前置。若实现时确有无法满足的依赖需求，先记录取舍，不能默默改为套壳旧体系。

计划在 U1 增加以下命令；本轮尚不存在，也未运行：

```text
npm run ui:dev          # 仅启动本地 Vite 页面预览，默认绑定回环地址
npm run ui:build        # 独立预览构建，输出到隔离缓存目录
npm run ui:typecheck    # 新 UI 与预览的独立类型检查，不先构建 Harness 包
```

配置计划：`vite.ui.config.ts` 使用 `ui-preview` 作为独立 HTML 入口并复用 React 插件；不加载 `electron.vite.config.ts`。构建/开发缓存放 `.vite/ui-preview/` 下具名子目录，与 `.vite/agent-dev/` 分离；不得输出到生产 `out/**`、生产 `dist/**` 或自动加入 Electron 多页面入口。清理只作用于本次 UI 缓存。

独立类型检查使用相应配置覆盖新目录和新 Vite 配置，不继承旧业务路径依赖作为运行前提。现有 web 类型检查仍应能覆盖新增前端文件；本地开发快速检查不代表豁免仓库检查。

工程检查补充：

- U1 新增 `tsconfig.ui.json`，仅覆盖新 UI、预览及独立 Vite 配置，使用独立编译选项，不继承旧 renderer 的业务别名和全局声明；不得通过声明 `desktopApi` 消除错误。
- 当前 `tsconfig.web.json` 已包含 `src/renderer` 下 TS/TSX；桌面目录迁移时须同步覆盖 `app/renderer`，新增 UI 继续受全仓检查覆盖，独立配置不是排除全仓检查的手段。
- 当前 Vitest 默认 Node 环境；UI 行为测试按现有测试命名方式显式使用 jsdom，复用现有 React act 设置，不全局改变其他测试的运行环境。
- U1 建立 UI 边界检查并纳入仓库静态检查链路：解析 TS/TSX 模块和 CSS 依赖，禁止新体系直连旧 UI/业务、预览直连私有机制及 UI 反向依赖预览。复用现有脚本工具能力，不引入新的规则框架；本地 UI 检查不以前置构建 Harness 为代价。

组件行为回归复用 Vitest/Testing Library 现有能力。新行为测试覆盖消费者可见的边界，不能锁定源码、文件数、CSS 类名或简单转发。用真实浏览器检查最终表面；组件测试不能替代视觉、命中测试和焦点操作。
